# 0000. 使用 Markdown 记录架构决策 (ADR)

- **状态**: Accepted
- **日期**: 2026-09-17
- **决策人**: Team Lead / Architect

## 背景 (Context)
随着项目演进与多 Agent 协同编码，许多关键架构设计、重大 Trade-off 和临时妥协（Workaround）如果仅停留在对话框或模糊注释中，容易造成信息丢失，后续开发者可能会误删或做出冲突改造。

## 决策 (Decision)
我们决定使用轻量级 Markdown 格式记录所有重大架构决策，统一存放在 `docs/adr/` 目录下，文件命名遵循 `000x-xxx.md`。

记录 ADR 的三大触发要素：
1. **不可逆 / 推翻成本高**；
2. **缺乏背景令人费解的妥协**；
3. **多选一的真实权衡**。

## 后果 (Consequences)
- 优点：架构演进有据可查，防止反复讨论已否决的方案。
- 缺点：每次重大决策需额外维护一份文档（由 Agent 在 Phase 1 或 Phase 3 自动固化）。
